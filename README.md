# Text Scoring Service

Учебный ML-сервис для определения тональности русскоязычных отзывов.
Стек: **Python 3.12, FastAPI, scikit-learn, MLflow, Docker Compose, Prometheus**.

Сервис принимает текст, возвращает `positive` / `negative`, оценку позитивности
от 0 до 1 и версию модели. В проект включены обучение, API, трекинг экспериментов,
структурированные логи, мониторинг дрейфа, тесты и воспроизводимый замер latency.

Модель — TF-IDF по словам и биграммам + LogisticRegression. Встроенные 80 отзывов
написаны вручную для демонстрации. Это небольшой учебный датасет, не внешний
бенчмарк и не подтверждение качества на реальных отзывах. Выделенной нейтральной
категории нет. Значения score и confidence не калиброваны.

## Самый простой запуск на Windows

1. Установите **Python 3.12** с Python Launcher (`py`).
2. Распакуйте архив целиком и откройте папку проекта.
3. Запустите **`start.bat`**. При первом запуске понадобятся интернет и время
   на установку библиотек. Скрипт создаст окружение, обучит модель, запишет
   эксперимент в MLflow и запустит API.
4. Откройте **http://127.0.0.1:8000/docs**.
5. Выберите `POST /score` → `Try it out`, введите JSON и нажмите `Execute`:

```json
{"text": "Отличный товар, качество хорошее"}
```

Поля ответа: `label`, `positive_score`, `confidence`, `model_version`.
Для остановки нажмите Ctrl+C в консоли.

Чтобы увидеть эксперименты, отдельно запустите **`mlflow_ui.bat`** и откройте
http://127.0.0.1:5000. Эксперимент называется `text-scoring`; в нём есть
параметры обучения, Accuracy, F1, ROC-AUC и артефакты модели.

При повторном запуске `start.bat` использует существующую модель. Чтобы
обучить заново, остановите API и выполните `.venv\Scripts\python -m scripts.train`.

## Запуск из терминала

Из корня проекта создайте и активируйте окружение:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
```

Linux / macOS:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
```

После активации команды одинаковые:

```bash
python -m pip install -r requirements-dev.txt
python -m scripts.train
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

Модель загружается один раз при старте. Без артефактов сервис завершится с
понятной ошибкой; скрытого обучения во время запросов нет.

В другом терминале с тем же окружением запустите MLflow:

```bash
mlflow server --host 127.0.0.1 --port 5000 --backend-store-uri sqlite:///mlflow.db --allowed-hosts localhost:5000,127.0.0.1:5000
```

## Docker

Установите Docker Desktop с поддержкой Compose, перейдите в папку проекта:

```bash
docker compose up --build
```

Compose сначала запускает MLflow, затем одноразовую задачу обучения и после её
успешного завершения — API. Порты доступны только с этого компьютера:

- Swagger: http://127.0.0.1:8000/docs
- MLflow: http://127.0.0.1:5000
- Метрики: http://127.0.0.1:8000/metrics
- Мониторинг дрейфа: http://127.0.0.1:8000/drift

Модель, MLflow SQLite и артефакты MLflow сохраняются в именованных томах.
API получает том модели только для чтения; контейнеры работают от непривилегированного пользователя.
Остановка: `docker compose down`. Тома сохраняются.
После изменения датасета остановите API, запустите `docker compose run --rm train`,
затем `docker compose up -d api`. При изменении кода или CSV предварительно
выполните `docker compose build`.

Docker CLI и daemon в среде разработки этого архива отсутствовали: Compose
проверен структурно, но сборка образа и запуск контейнеров здесь не выполнялись.
Локальный запуск API, обучение, HTTP-интеграция MLflow и загрузка артефактов проверены.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/health` | Процесс отвечает |
| GET | `/ready` | Модель загружена; возвращает её версию |
| GET | `/model` | Метаданные, параметры и метрики обучения |
| POST | `/score` | Скоринг одного текста |
| POST | `/score/batch` | Скоринг списка до 32 текстов |
| GET | `/drift` | PSI и состояние окна мониторинга |
| GET | `/metrics` | Метрики в формате Prometheus |
| GET | `/docs` | Интерактивный Swagger |

Пример тела пакетного запроса:

```json
{"texts": ["Спасибо за быструю доставку", "Товар сломался, качество плохое"]}
```

Ограничения: непустые строки, максимум 3000 символов на текст, максимум 32 текста
на запрос; лишние поля запрещены. Ошибки валидации возвращают HTTP 422.
`positive_score` — выход `predict_proba` позитивного класса. При score ≥ 0.5
метка — positive. `confidence = max(score, 1 - score)`; это также не гарантия
правильности. Из неизвестных слов модель может выдать оценку около базовой доли класса.

## Логирование и метрики

Каждый HTTP-запрос получает `X-Request-ID`. JSON-лог содержит идентификатор,
шаблон маршрута, HTTP-метод, статус и время обработки. Исходный текст, query
параметры, тело запроса и заголовки в лог не записываются. Рекомендуемый запуск
использует `--no-access-log`, чтобы стандартный access log также не выводил URL.

`/metrics` отдаёт:

- `http_requests_total` — количество запросов по маршрутам и статусам;
- `http_request_duration_seconds` — гистограмму серверного времени обработки;
- `texts_scored_total` — количество обработанных текстов по предсказанным меткам;
- `data_drift_psi` — PSI для каждого признака;
- `data_drift_detected` — 1 при сигнале, 0 без сигнала, −1 до накопления выборки;
- `data_drift_window_samples` — число наблюдений в окне.

Неизвестные пути объединяются меткой `unmatched`, чтобы произвольные URL не
создавали новые серии метрик. Готовый сервер Prometheus и Grafana не включены:
endpoint подготовлен для подключения к внешнему сборщику.

## Дрейф данных

В памяти хранится до 1000 последних векторов признаков, без самих текстов.
Монитор сравнивает их с признаками **обучающей части**, не тестового набора:

1. Длина текста в символах.
2. Число слов, выделенных токенизатором.
3. Доля русских букв среди всех букв.
4. Доля слов вне словаря TF-IDF (OOV).
5. Оценка позитивности модели.

Для каждого признака рассчитывается Population Stability Index по фиксированным
квантильным интервалам обучающей выборки. Нулевые доли сглаживаются; бесконечные
границы учитывают выход новых значений за диапазон обучения. Сигнал появляется,
когда хотя бы один PSI ≥ 0.2. Это демонстрационный эвристический порог, требующий
калибровки на реальных потоках, особенно при маленькой эталонной выборке.

До 50 наблюдений статус — `insufficient_data`, а `drift_detected` равен `null`.
Указанные 50 наблюдений — технический минимум, не гарантия статистической надёжности.
Дрейф распределений не доказывает ухудшение качества: для этого нужны новые
размеченные отзывы. Даже намеренно повторённые обычные запросы могут дать сигнал.

Демонстрация изменения входов при работающем API:

```bash
python -m scripts.demo_drift --count 100
```

Скрипт отправит длинные английские тексты, затем выведет отчёт. Монитор не
переобучает модель и не блокирует ответы автоматически. Окно обнуляется при
перезапуске. Используйте один API worker: несколько процессов получат независимые
окна. Для масштабирования понадобится общее хранилище событий и отдельный монитор.

Настройки через переменные окружения:

| Переменная | Значение по умолчанию |
| --- | --- |
| `MODEL_DIR` | `artifacts` |
| `MLFLOW_TRACKING_URI` | `sqlite:///mlflow.db` |
| `DRIFT_WINDOW_SIZE` | `1000` |
| `DRIFT_MIN_SAMPLES` | `50` |

## Замер latency

При работающем API:

```bash
python -m scripts.benchmark --requests 300 --warmup 30 --concurrency 1 --log-mlflow
```

Отчёт сохраняется в `reports/benchmark.json`, а с `--log-mlflow` — также в
эксперимент `text-scoring-benchmark`. Для контейнерного MLflow задайте
`MLFLOW_TRACKING_URI=http://127.0.0.1:5000` в терминале клиента.
Для другого адреса используйте `--url`, для другого файла — `--output`.

Измеряется **полный HTTP round trip с чтением ответа**, после прогрева,
на трёх коротких заранее заданных фразах. Загрузка модели и обучение исключены.
Соединения переиспользуются. Ошибки учитываются отдельно; при наличии ошибок
скрипт возвращает ненулевой код. Это короткий локальный тест, не SLO и не
исчерпывающий нагрузочный тест. Длинные тексты и реальные сети дадут другие значения.

Проверенный результат 28.10.2026 на Linux, Python 3.12.14, AMD EPYC 9V74:

| Режим | Запросы | Прогрев | p50, мс | p95, мс | p99, мс | Ошибки |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Последовательно | 300 | 30 | 2.19 | 3.17 | 5.27 | 0 |
| Конкурентность 8 | 200 | 10 | 22.95 | 29.78 | 35.36 | 0 |

Среднее в последовательном тесте — 2.62 мс; максимум — 83.73 мс.
Сырые отчёты с параметрами измерения находятся в `reports/`.

## Обучение на своих данных

Подготовьте UTF-8 CSV с колонками `text,label`, метками `positive` и `negative`.
Классы должны содержать минимум по 10 строк; для практического качества нужно
существенно больше разнообразных размеченных данных. Пустые и дублирующиеся
тексты отклоняются. Остановите API, затем:

```bash
python -m scripts.train --data data/my_reviews.csv
```

Модель обучается на 75% данных; 25% отложено для проверки со стратификацией и
`random_state=42`. Для реального проекта разделяйте близкие отзывы по пользователю,
товару или времени, чтобы исключить утечку. После обучения перезапустите API.

Результат демонстрационного набора: **Accuracy 0.60, F1 0.60, ROC-AUC 0.74**,
20 отложенных примеров. Это проверка работоспособности пайплайна; исходные тексты
и предсказания теста сохраняются в `artifacts/evaluation.json`. Показатели не
подменяются результатами на обучении. Подбор гиперпараметров по этому тесту не выполнялся.

MLflow сохраняет параметры, метрики, хеш датасета, модель, эталонные признаки и
метаданные. Модель загружается из локального bundle, идентифицируется хешем;
MLflow используется для трекинга и хранения артефактов, не как Model Registry.
При недоступности трекинга обучение сообщает об ошибке, а не скрывает её.
Для тестов или работы без трекинга предусмотрен флаг `--no-track`.

## Проверка

```bash
python -m pytest -q
python -m scripts.train
python -m scripts.verify
```

14 тестов проверяют контракты API, валидацию, пакетный скоринг, логи без текста,
метрики, PSI, недостаточную выборку, ограничение окна и конкурентные обновления.
`scripts.verify` запускает отдельный настоящий Uvicorn на порту 18000, делает
последовательный и конкурентный HTTP-замеры, проверяет дрейф и останавливает сервер.
Он перезаписывает демонстрационные отчёты в `reports/`.
В тестовой среде есть предупреждение Starlette о будущем переходе TestClient
с httpx на httpx2; при зафиксированных версиях все проверки проходят.

В `.github/workflows/tests.yml` подготовлен workflow для запуска тестов на GitHub.
Файл добавлен в проект; сам workflow в GitHub здесь не запускался.

## Структура

```text
app/              API, модель, PSI-монитор
scripts/          обучение, benchmark, демонстрация и HTTP-проверка
data/             80 демонстрационных размеченных отзывов
tests/            14 автоматических тестов
reports/          реальные замеры и результаты проверки
Dockerfile        образ Python 3.12
compose.yaml      MLflow → обучение → API
start.bat         простой запуск в Windows
mlflow_ui.bat     запуск интерфейса MLflow в Windows
```

Артефакты модели и база MLflow создаются при обучении и исключены из Git.
Зависимости верхнего уровня закреплены по версиям; полного lock-файла всех
транзитивных зависимостей и фиксации digest базового образа нет.

Проект предназначен для локального портфолио. Перед публичным размещением
понадобятся аутентификация, TLS, ограничение размера HTTP-тела и частоты запросов,
отдельная политика хранения данных и наблюдаемость. Сохранение joblib подходит
только для доверенных собственных артефактов: никогда не загружайте чужие файлы
моделей. Проверка SHA-256 здесь обнаруживает повреждение, но не заменяет подпись.
